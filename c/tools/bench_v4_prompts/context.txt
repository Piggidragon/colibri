This is a fixed engineering corpus for repeated inference measurements. It describes one Linux workstation running a large sparse language model. The host has ten physical cores split between performance and efficiency designs, sixteen hardware threads, 32 GiB of dual-channel DDR4 memory, two solid-state drives, and a headless graphics card with 12 GiB of memory. The checkpoint contains dense tensors, an output head, routed experts, attention state, and speculative-drafting tensors. Routed expert records dominate storage traffic. A cache hit consumes memory bandwidth but no storage bandwidth; a miss reads a complete record from disk before computation can continue.

The resource planner begins with MemAvailable. In automatic mode it reserves a fraction for the operating system, subject to conservative lower and upper bounds. An explicit process budget below MemAvailable leaves everything outside that budget to the operating system and therefore does not subtract the automatic reserve again. The planner also reserves two maximum-size dense layers, context-dependent attention state, hidden activations, scratch space, and any drafting allowance. Only the remainder can become expert-cache slots. Since slots are allocated per sparse layer, small byte changes become stepwise capacity changes.

Context accounting must use the checkpoint geometry. Every layer owns a fixed sliding window. Compressed-attention layers add rows at their compression ratio, and indexer layers add a second compressed stream with a smaller head dimension. Reserving for a context much larger than the actual workload wastes expert residency. Reserving too little rejects a prompt or makes a comparison meaningless. A benchmark records both the requested context and the prompt token count so that later results can be checked rather than trusted from a label.

The measurement protocol is deterministic. The prompt bytes live with the source tree, generation is greedy, seeds are fixed, and every relevant environment override is stored next to the result. A cold run flushes filesystem page cache immediately before engine startup. A warm run executes an unmeasured warm-up with the same prompt and configuration, then launches the measured process without flushing pages. Usage-history writes are disabled during measurement so the warm-up cannot alter placement for the measured process. Cold and warm are different experiments and must never be pooled silently.

The report separates prefill from decode. Time to first token covers the prompt forward pass and first output decision. Decode throughput uses only tokens produced after the first token because the engine reports their elapsed interval separately. Expert telemetry includes requests, hits, misses, and payload bytes read. Disk gigabytes per token divides payload bytes by the number of model-forward input tokens, including prompt inputs and generated inputs that were fed back. The report also records planned cache capacity, slot count, projected RAM, computed attention-cache size, thread count, revision, and dirty-worktree state.

Performance claims need physical bounds. Each decoded token activates several experts in every sparse layer, moving multiple gigabytes of weights through main memory even when every expert is resident. Sustainable memory bandwidth therefore places an upper bound on target-only decode. Speculative decoding may amortize expert unions across several accepted tokens, but its proposal count and acceptance rate must be shown. A number beyond the target-only bandwidth ceiling triggers an audit of token counters, interval definitions, cache state, and speculative acceptance before it becomes a claim.

Correctness remains the first gate. Defaults preserve model precision and router semantics. Lossy storage formats, altered top-k choices, approximate reductions, and changed expert selection require explicit independent switches and dedicated accuracy evidence. A reserve knob is not a hard allocator limit; lowering it only makes the plan more optimistic. Invalid environment text falls back to the documented default, while valid numeric values are clamped to a safe range. Tests cover the default, both clamps, malformed input, and a representative explicit value.

The final benchmark artifact is one JSON object per line. Append-only files make repeated measurements easy to diff and ingest without screenshots. Human-readable stdout contains exactly one compact summary line, while failures go to stderr and do not append a result. The full record retains paths, hashes, cache state, configuration, raw counters converted into named metrics, and enough metadata to reproduce the command. Measurements that cannot be run because a checkpoint or dependency is absent stay explicitly pending; estimates never masquerade as observations.
